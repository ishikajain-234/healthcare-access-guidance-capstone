# Live Demonstration Disclosure

**Mandatory Spoken Opening:**  
Every live demonstration of the Healthcare Access Guidance Prototype must begin with this exact verbal statement:

> “This is a student prototype using fictional synthetic data. It is not connected to any hospital, government system, PM-JAY system, ABDM system, ORS system, or eligibility database. It does not determine eligibility, coverage, approvals, hospital availability, cashless treatment, medical need, or legal status.”

---

## Key Talking Points for Evaluators
1. **Academic Demonstration Context:**
   * This project is built by 2nd-year undergraduate engineering students demonstrating Application Programming (state machines, strict input validation, REST API) and Data Engineering (event logging, ETL pipelines, analytical modeling).
2. **Intentional Scope Boundaries:**
   * Explain why the application avoids free-text inputs: to eliminate PII leakage and prevent lay users from seeking unassisted clinical advice.
   * Explain why no live government or hospital APIs are used: to maintain complete data safety, eliminate legal liability, and work within an honest academic simulation boundary.
3. **Data Authenticity Disclaimer:**
   * Remind evaluators that all package codes (`DEMO-ALPHA-001`, `DEMO-BETA-002`, `DEMO-GAMMA-003`) are fictional mock records with no real-world clinical pricing or government backing.
